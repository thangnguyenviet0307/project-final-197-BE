# Hero slides API

Home hero content is stored in `hero_slides`; there are no built-in category banners or automatic production writes. Add the first slide through **Hero trang chủ** at `/auth/hero-slides` after deployment. Empty configuration displays a generic storefront welcome hero with a /shop CTA and the same reserved height; failures retain a retry state rather than old category demo slides.

## Endpoints

| Method | Endpoint | Access |
| --- | --- | --- |
| GET | `/api/v1/hero-slides/public` | Anonymous; active slides with active, non-deleted categories only |
| GET | `/api/v1/hero-slides` | Admin |
| POST | `/api/v1/hero-slides` | Admin |
| PATCH | `/api/v1/hero-slides/:id` | Admin; requires expectedVersion |
| DELETE | `/api/v1/hero-slides/:id` | Admin; JSON body with expectedVersion |

Admin/staff authentication uses the existing bearer token transport. Staff and customer tokens receive 403 on management endpoints. Named public routes precede authentication.

### Create

```json
{
  "category": "0123456789abcdef01234567",
  "title": "Your own hero title",
  "description": "Your own category introduction",
  "imageUrl": "https://example.com/hero.jpg",
  "sortOrder": 1,
  "isActive": true
}
```

`category` must reference an active, non-deleted category. `title` is required, trimmed, 1-200 characters. Description is plain text, trimmed, up to 1000 characters (default empty). `imageUrl` is HTTP(S), up to 2048 characters, or null (default); null uses the category icon when present, otherwise a neutral dark background. The API does not download supplied images. `sortOrder` is an integer 0-10000 (default 0); `isActive` defaults true. All input schemas reject unknown fields, including custom CTA overrides. Maximum 50 slides, including inactive slides.

The button is generated by the frontend as `Khám phá <current category name>` and links to `/shop?category=<category ID>`. Multiple slides may reference the same category with different copy. Sort order is ascending, then ID ascending for stable ties.

### Update

```json
{ "expectedVersion": 0, "title": "Updated title", "imageUrl": null }
```

Send changed fields only. Omitted fields are retained. Changing category or enabling a slide validates its category inside the existing relations transaction. Inactive/deleted category references make the slide invisible publicly; there is no cascade from a category change into slide content. Admin lists retain these slides so an administrator can select a replacement category or remove them.

### Delete

```json
{ "expectedVersion": 1 }
```

Use `__v` from the original admin response for updates/deletes. Stale versions, invalid/inactive references and exceeding the cap return 409; missing slides return 404; invalid identifiers/inputs return 400. The admin editor preserves failed drafts and blocks stale writes until explicit reload/review; background refetch never upgrades the editing version. Deletion requires confirmation in the UI.

Responses follow the existing JSON envelope (`data` is an array for lists, a slide for create/update). Public responses expose only `_id`, category (`_id/name/icon`), title, description, imageUrl and sortOrder; internal version/status/timestamps are private. No pagination is needed under the 50-slide cap. Successful create returns 201; reads/update/delete return 200.

Hero data shares the `hero-slides` query prefix. Admin changes and category changes invalidate relevant hero queries; the existing cross-tab business-change signal refreshes storefront/admin tabs. The 6.5-second rotation, left selectors, shared container alignment and responsive hero layout remain in use.
